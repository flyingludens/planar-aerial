# 调查板与正文的关系：事实出处与过期检测

状态：**已实现**（2026-10-26）。实现范围：待实现清单 1–4 全部完成；清单 5 的测试
覆盖了四条规则、apply 打戳、混合事实、上下文标注。

实现备注（与原 spec 的差异）：

- `applyMosaicProposal` 接受第三个参数 `provenance`，手工路径（merge 流程、手动建卡）
  走同一函数但不传它，实体和连线都显式落到 `source: 'board'`
- 客户端在 runApply 里、**flush 之后**才算章 hash：hash 先算会把 flush 推迟到点击之后，
  破坏"apply 前先落盘"的顺序承诺；flush 后内存里的章正文就是刚写盘的内容
- 浏览器侧用 `crypto.subtle`，与 lib 的 sha256 对同一 UTF-8 文本字节一致

## 问题

调查板（mosaic.json）和正文（book.json 的 nodes）没有从属关系，是两个独立的存储。
工作流里二者互为源：

- 灵感、设定、人物关系**先**记在板上（此时正文里还没有它）
- 板是写正文时的上下文（`buildFacts`），保证 AI 不写崩
- 正文写成后可能与板子冲突，"检查本章"提取事实、经作者确认后**更新**板子

方向取决于环节：创作前板是源，创作后书是源。这是真实工作流，不是缺陷。

## 决策：不搞"谁是本源"，搞"写入过闸 + 冲突可见"

不做任何自动同步（正文几万字，板子是结构化卡，自动同步要么改错正文，要么把 AI
的幻觉写进设定）。守两条：

1. **单一写入路径**：板子的变更只能走提案 → 作者确认（现状已有，保持）
2. **冲突可见**：检测到漂移时标注，不静默

### 事实分两类

板子上每个事实（entity / edge）加来源标记：

- `source: 'board'` —— 手动建的卡 = 作者意图。**正文没写到它不代表冲突**，
  优先级最高，不需要正文背书
- `source: 'chapter'` —— 从某章提取、经确认 = 声称"正文里是这么写的"。
  正文改了它就可能过期，是唯一需要检测的对象

## 过期检测：方案 C（note 包含检测为主，hash 兜底）

### 判定规则（最终版：一视同仁）

`source === 'chapter'` 的事实，对照其来源章节的正文：

1. `chapter.text` **逐字**包含 `fact.note` → **valid**（原句还在）
2. 逐字不含，但章 hash 没变（`fact.basedOn.hash` === `hashText(chapter.text)`）
   → **valid**。正文从接受至今一个字节都没动过，当时判定成立现在就成立；
   对不上只说明模型提取时转述了原句而不是逐字引用。防的是**转述容忍**
3. 逐字不含，且章 hash 变了 → **suspect**（值得看一眼，不是错误）
4. `fact.basedOn.chapter` 指向的章节已不存在 → **orphaned**（章节被删）

### 不做标点特判（决策记录）

中途曾加过"去标点匹配"：认为逗号删在事实自己的句子里不该报警。已**移除**，
理由是两个概率的不对称：

- 事实句子内部被改标点、且改后词序不变：**低频**事件
- 剥离表本身的失配风险：符号种类繁杂（全角半角、引号变体、未来出现的新符号），
  每一类都是"本该报警却被静默放行"的漏报机会——而漏报的代价是过期事实
  无声地喂给模型，比误报（多一行提案，检查本章时顺手清掉）贵得多

结论：**一视同仁**。改了任何字节，只要原句找不到了，就报 suspect，
让下一次检查本章去分辨语义变没变。Uniformity over cleverness。

### 为什么不用纯 hash

sha256 全或无：改 3 个字，8 条事实全部嫌疑，其中若干条实际未受影响。
note 包含检测把灵敏度降到"这句的词真的不在了"。

### suspect 的语义

**不是错误状态**，是"这一章动过，值得看一眼"。suspect 事实继续参与上下文
（照常喂给 AI），只带标注。清掉它的方式：下一次「检查本章」——AI 重读正文，
提案里对每条 suspect 给出结论（正文仍支持 → 刷新 basedOn；矛盾 → 更新提案；
正文没提 → 来源失效标记）。复查本来就是那个按钮的职责，不新增按钮。

## 性能（已实测，2026-10-26）

| 操作 | 耗时 |
|---|---|
| 300 条事实 × 单章 2 万字 includes | 0.96ms |
| 全书 50 章、300 条事实各归各章 | 1.01ms |
| 对照：整本 25 万字 sha256 | 1.5ms |
| 对照：一次 AI 调用 | 2000~20000ms |

检测只在两个时机跑：写盘后、组装上下文时。按键时不跑。结论：成本可忽略。

## 存储改动

`mosaic.json` 的 entity / edge 各加两个字段，`normalizeMosaic` 白名单放行：

- `source: 'board' | 'chapter'` —— 缺省 `'board'`（现有数据全是手动的）
- `evidence: string[]` —— 提取时的原句（沿用 `truth.note` 的"逐字原句"约定）
- `basedOn: { chapter: <章节id>, hash: <sha256> }` —— 仅 `chapter` 来源的事实有

## 不做的事

- 不自动改写正文
- 不自动删改板上的事实（suspect 只标注）
- 不做双向自动同步
- 改名不做自动全文替换（名字是正文和板子共享的最小事实，改名应弹确认，
  属于后续 UI 决策，不在本方案内）
